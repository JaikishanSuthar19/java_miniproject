Context • Problem Statement 11

Problem Statement & Real-World Motivation

Modernizing university course enrollment workflows and preventing resource contention.
Legacy Friction
Traditional Registration Pain Points
Uncontrolled Over-Enrollment: Without concurrent seat locking, popular classes fill past physical classroom capacity.
Duplicate Enrollments: Students register for duplicate sections, depriving peers of limited vacant seats.
Disconnected Faculty Records: Instructor assignments and department directories maintained in silos.
Credit Overload: Students enroll in excessive workloads without prerequisite or semester credit checks.
Our Architecture
The Engineered Solution
Real-Time Seat Management: capacity vs. registeredStudents enforced at the domain entity level.
Semester Credit Cap: Hard stop at 18 credits to ensure balanced academic schedules.
Full Faculty Integration: Dedicated Faculty Directory with live search and add capabilities.
Audit Trail Preservation: Cancelled courses preserve history in a chronological LinkedList.
Compliance • Syllabus Requirements

Core Objectives & Syllabus Alignment

Structured mapping to the 8 core objectives specified in the Mini Project 11 guidelines.
1. Entity Management
Models for Student, Course, Faculty, and Registration with strict data encapsulation.
2. Registration Engine
Real-time enrollment, cancellation, duplicate prevention, and credit calculation logic.
3. Capacity Monitoring
Automatic vacancy calculation with visual high-contrast AVAILABLE and FULL indicators.
4. Array Storage
Fixed Course[] array for initial course offerings with dynamic reallocation safety.
5. LinkedList Log
LinkedList<Registration> maintaining sequential event history for institutional auditing.
6. HashMap Search
O(1) constant-time record retrieval for Students, Courses, and Faculty by unique ID.
7. TreeMap Sorting
Self-balancing Red-Black Tree maintaining courses naturally sorted by Course ID.
8. Modern Swing GUI
Desktop experience styled with FlatLaf, responsive CardLayout, and live state synchronization.
Algorithms • Collections Architecture

Java Collections Framework Deep Dive

Technical comparison and algorithmic justification of chosen data structures.
Fixed Memory
Course[]
Time: O(1) Index Access

Fulfills Objective 4. Used in DataStore for predefined initial courses. When courses exceed length, System.arraycopy dynamically doubles array capacity.

Audit Trail
LinkedList<Reg>
Time: O(1) Append

Fulfills Objective 5. Represents a chronological event log. Appending registrations occurs in O(1) time without contiguous memory reallocation.

Fast Lookups
HashMap<ID, T>
Time: O(1) Search

Fulfills Objective 6. Indexes Students, Courses, and Faculty by unique ID. Enables instant authentication and O(1) detail lookups during registration.

Self-Sorting
TreeMap<ID, C>
Time: O(log N) Search

Fulfills Objective 7. Backed by a Red-Black Tree. Guarantees courses are always presented in alphabetical order across tables without sorting overhead.
